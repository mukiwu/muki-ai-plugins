# 報告規格

下面說明每一區要放什麼、資料從哪來

## 頁面結構

| 區塊 | 內容 | 資料來源 |
|---|---|---|
| 頂部導覽 | 固定在上方的章節連結，捲動時標示目前章節 | |
| 開場 | 標題、一句說明、6 格數字（對話檔總數、人參與的 session、訊息數、字數中位數、附截圖訊息數、commit 數），下面一行註明排除了幾個自動化 session | `summary.counts` |
| 00 時間軸 | 每個 session 一列，長條表示起訖日，大型 session（80 則以上）用 accent 色，Codex 用 link 色，點列顯示這個 session 在做什麼、skill、訊息數、commit 數；旁邊放每日訊息數柱狀圖和訊息類型長條 | `summary.sessions`、`summary.days`、自己讀完後寫的摘要 |
| 01 Skill 排行 | 橫向長條，分色顯示使用者打的與 AI 叫的，可切換篩選，點長條看說明；下方表格對照 CLAUDE.md 宣稱的路線與實際次數 | `summary.skills`、使用者的 CLAUDE.md |
| 02 工作流程 | 泳道圖（用 diagram-design 畫，沒裝就照 diagram-fallback.md，使用者與 AI 兩條道）、每一步的文字卡片、除錯流程圖、換路的真實例子、AI 用到的工具 | 讀完對話後歸納 |
| 03 溝通方式 | 切換開發與除錯兩組模式，每組 5 到 8 條，每條有標題、說明、原話；最後一張卡放讓使用者不耐煩的原話 | 讀完對話後歸納 |
| 04 原話庫 | 30 到 50 張卡，可依分類（開發、Debug、修正、記錄、收尾）與關鍵字篩選，每張附 session id 與一句解讀 | 原話 |
| 05 建議 | scope 判斷表、可展開的 skill 建議卡（優先度、scope 徽章、證據、做什麼、建議放哪裡與路徑、SKILL.md 草稿含複製按鈕）、不必做成 skill 的其他優化 | 歸納結果 |
| 06 建議移除的 skill | 開場三個數字（已安裝、這段期間用過、建議移除），依四類分組的表格：skill 名稱、來源與 scope、這段期間次數、所有專案次數與最後使用日、判斷理由（搜了哪些關鍵字、找到什麼）、移除指令；每列有勾選框，勾選後下方即時組出可一次複製的移除指令；停用中的 plugin 另列一行 | `summary.installed_skills`、關鍵字搜尋結果 |
| 頁尾 | 資料路徑、去重與分類方式說明、整理日期 | |

多專案合併時另外加：開場數字按專案拆開、時間軸與原話庫加專案篩選 chip、skill 排行點開顯示用在哪些專案、建議卡標出證據來自哪些專案

## 圖表規則

- 長條、柱狀要依同一個比例尺畫，數值差太多時改用平方根比例並在下方註明
- 顏色都走 CSS token，淺色與深色主題都要看得清楚
- 流程圖用 inline SVG，填色與線條用 class 對應 token，不寫死色碼，這樣才會跟著主題切換
- 流程圖遵守 diagram-design 的連線規則（fallback 裡有同一份）：直角圓弧轉折、標籤離線 6 到 10px、座標是 4 的倍數、accent 最多兩個
- 手機寬度下圖表容器可以橫向捲動，整頁不能

## 版面防呆規則

這些都是實際跑版踩過的，寫版面時就照做，發布前再用 check_layout.py 驗證

**圖表**

- 長條與柱狀的比例尺一律用資料的最大值算，不可以寫死一個上限，資料變了圖就會衝出容器蓋到標題
- 柱狀圖不要在每根柱子上放數字，柱子一窄數字就互相重疊；改成滑過顯示，最大值寫在圖的標題列
- 圖表容器的高度與上方留白要固定，標題和圖分開成兩個區塊

**流程圖（SVG）**

- 節點文字要算過寬度：主標 12px 的中文每字約 12px，副標 9px 等寬字的中文每字約 9px、英數約 5.4px，文字寬度要小於節點寬度減 16
- 112px 寬的節點，主標最多 8 個中文字，副標最多 10 個中文字或 17 個英數字，放不下就縮短文字或加寬節點，不要靠自動縮小
- layout-guard.js 的自動縮小只是最後保險，檢查腳本仍然會把縮小和截斷列成問題
- 菱形判斷框的文字只能放在中間那一行，最多 6 個中文字

**表格與清單**

- 文字多的列不要做成三欄以上的並排格子，欄位一窄說明就會被擠成一行兩三個字；改成上下排列：名稱與數字一行，說明放下一行全寬
- grid 或 flex 裡放文字的子元素都要加 `min-width: 0`，長英文、路徑、指令加 `overflow-wrap: anywhere`
- 真正需要並排比較的表格才用 table，並包在 `.tbl-wrap` 讓它可以橫向捲動

**資料清理**

- 使用者訊息裡的 HTML 實體（例如 `&#x20;`）要先換成一般字元再放進頁面

## 歸納時要找的訊號

開發：

- 開場第一句怎麼問，是先要全貌還是直接下指令
- 會不會要 AI 用畫面上的文字回答
- 規格怎麼對齊（表格、報告、prototype）與定案後存到哪裡
- UI 怎麼決定（出多個方案選、混搭）
- 任務怎麼切（編號清單、一次一步）與 commit 頻率
- 誰測試（使用者自己測還是讓 AI 開瀏覽器）

除錯：

- 回報格式（截圖、現象、預期）
- 是否要求先查原因不准動手
- 看不到執行狀態時怎麼辦（請 AI 加 console、使用者貼回）
- 是否主動問影響範圍
- 使用者用領域知識反駁 AI 的時刻
- 卡關時的退路（換做法、換工具如 Codex）
- 修正方向與不耐煩的原話，例如還原、改回、不是我要的、雞婆、擅自

可做成 skill 的訊號：

- 同一段話或同一種請求出現三次以上，或出現在三個以上 session
- 使用者每次都要補同一句限制
- 使用者說過我問過很多次了這類話
- 為了同一件事連續試了好幾個 skill

## 踩過的坑

- 同一個 plugin 的 skill 名稱會帶前綴（例如 `lore:lore-guard`），比對使用次數時名稱和前綴版都要算，腳本已處理
- 很多 skill 是被別的 skill 或子代理叫用，不是使用者直接用，移除前要搜依賴，不然會弄壞別的流程

- 自動化 session 可能佔大多數檔案（實測過一個專案 151 個檔案裡有 133 個），不排除會讓數字全錯
- skill 有兩種叫法：使用者打 /指令（記在 command-name），AI 呼叫 Skill 工具，兩個都要算，而且要分開呈現
- 使用者在句子裡寫 用 /diagram-design，實際是 AI 叫的 Skill 工具，歸在 AI 那邊並在圖例說明
- 回溯或壓縮後的 session 會重複同一批訊息，腳本已用 uuid 去重，但重送的相同文字仍會存在，引用時挑一次就好
- artifact 頁面裡的按鈕不會把選擇傳回對話，選版類的建議要寫成在對話裡回覆
